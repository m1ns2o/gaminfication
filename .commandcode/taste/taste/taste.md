# Taste
- Communicates in Korean; respond in Korean. Confidence: 0.9
- Holds a high bar for UI polish: no text overflow or clipping, and paired form elements must share consistent heights and alignment. When one of a pair carries extra inline decoration (e.g., an icon on only one label) that breaks the match, prefers stripping it so both sides are symmetric rather than adding it to the other. When reporting one broken spot, expects similar issues to be found and fixed across the UI, not just the one reported. Confidence: 0.85
- Cares about responsive behavior at each breakpoint (desktop, tablet-ish width, mobile): e.g., a sidebar must keep a proper card frame (background/border/alignment) when it reflows to the top, and labels must remain fully readable. Prefers fixing via concrete CSS knobs (width, font-size, gap, padding) or simplifying/condensing content over leaving cramped or hidden text. Confidence: 0.8
- Strongly values consistency with existing patterns: when an element is built differently from its siblings (e.g., a fieldset `legend` straddling the frame border instead of a label sitting above the control), wants it reworked to "the same way as the others" — keep the semantic element but move the visual frame (border/background/padding) into an inner wrapper so the title sits above the panel like every other label. Confidence: 0.8
- Prefers collapsible sidebars/asides to fold horizontally (side-to-side) rather than vertically (up/down), so the toggle has real utility; the collapsed state should keep a slim icon/number rail instead of merely hiding content. Confidence: 0.8
- Expects requests carried through to a finished, polished state ("완성"), not partial patches. Confidence: 0.6
- Prefers consolidating redundant or near-duplicate navigation/menu entries into a single unified section rather than keeping overlapping items (e.g., merging separate "기본 설정" and "맵 템플릿" menus that effectively covered the same settings and broke tab switching). Confidence: 0.7
- Values smooth, natural animation motion and dislikes abrupt snaps or frame jumps when an animated value changes (e.g., a spinning die should ease onto its final face rather than snapping to it). Confidence: 0.7
- Prefers design-system coherence for spacing and color: new or revised sections should reuse existing spacing tokens and component families (e.g., answer-preview / content-counts / preview-action with soft color variants like amber-soft / indigo-soft) rather than introducing bespoke spacing/borders or repurposing context-specific components (e.g., room-prompt) that break visual unity with other editors. Confidence: 0.78
- Expects completion/result overlays (e.g., GAME COMPLETE) to be explicitly dismissible with a clear close affordance rather than persisting indefinitely, and that dismissing should fully restore board interactivity and reset for the next game/test session. Confidence: 0.72
- Prefers validating realtime/multiplayer features with 2+ concurrent participants in an end-to-end smoke test covering the full game flow (team play, simultaneous answering/timeout, and final results persistence) rather than single-user or isolated checks. Confidence: 0.68
- Prefers resolving text overflow by first condensing/editing the copy itself into shorter, concise sentences, then adding CSS layout safeguards (flex-wrap, min-width:0, overflow-wrap:anywhere, removing white-space:nowrap) to ensure graceful wrapping — rather than relying solely on truncation/ellipsis or leaving overflow. Confidence: 0.78
- Prefers dismiss/close actions placed after primary content (rankings, statistics) rather than directly under the header, following natural top-to-bottom reading flow so users review results before closing. Confidence: 0.72
- Prefers action cards with long text to use a stacked layout (icon+title header, description copy, full-width bottom button) to free text space rather than a cramped side-by-side icon/text/button arrangement. Confidence: 0.75
